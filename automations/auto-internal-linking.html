Auto Internal Linking

New posts linked in and out across the blog at publish time.

Read the runbook
01 · Opening

A new post opens like a new station.

Publishing a blog post in Webflow starts both engines. The post must be live, not a draft. Its two signals, inbound done and outbound done, start at red.

not linked yetlinked
02 · The register

Every post has a row of keywords.

The register is a Google Sheet with one row per post: its slug and a few short phrases. A tag says where they came from: gsc for queries the post ranks for in Search Console, ai for phrases Claude wrote from the post itself.

gscai
03 · The top 100

The busiest posts are the interchanges.

A second tab ranks the top 100 posts by Search Console clicks, with each post's category. Only these posts can link back to a new one.

04 · Inbound

The busiest posts link in.

The inbound engine looks for the new post's keywords in the top 100. Each match gets one link back to the new post, on the matching phrase. Same-category posts with no match get an Also read line instead: at most five, never the same post twice.

inbound linkAlso read
05 · Outbound

The new post links out.

The outbound engine finds older posts whose keywords appear in the new post and links those phrases to them. Links only go into paragraph text, never headings, tables, code or captions.

outbound link
06 · The log

Every link lands in the log.

Each link is appended to a log tab: when it was added, the post it sits in, the phrase that was linked, where it points, and whether it is inbound or outbound. Any link can be checked or removed from there.

inboundoutbound
07 · Refreshes

Edits to older posts are left alone.

An older post's two switches are already on, so when an editor updates it, neither engine runs and nothing gets relinked.

both switches on

Every new post is linked both ways within minutes of publishing.

No editor involved. Refreshes never set it off. Every link is on record.

Auto Internal Linking. When a new blog post is published in Webflow, two n8n engines link it into the rest of the site: one adds links from the new post to relevant older posts, the other adds links from the top older posts back to it, using a keyword register built from Search Console and Claude.

01Problem

Internal links were never added at publish time.

Internal linking is one of the few SEO levers fully in the team's control. New posts went out with no links pointing to them, older posts never pointed to newer ones, and retrofitting links across a 400-post blog by hand was a project nobody started.

02Flow

Two n8n workflows, the outbound engine and the inbound engine, both started by the same Webflow publish.

  1. 01

    Publish event and switches

    Both engines fire when a blog post is published. Each reads two switch fields on the post, Outbound Done and Inbound Done, and confirms the post is live, not a draft. If its switch is already on, the post is a refresh and that engine stops.

    Webflow publish event · Webflow CMS
  2. 02

    Read the keyword register

    Short matchable phrases per post come from a Google Sheet, along with the list of the top 100 posts by traffic.

    Google Sheets
  3. 03

    Outbound: link out

    The engine reads the new post, finds older posts whose keywords appear in it, inserts inline links in paragraph text and flips Outbound Done to true.

    Webflow CMS item update
  4. 04

    Inbound: link back

    The engine takes the new post's keywords and scans the top 100. Each matching older post gets one inline link back to the new one. Same-category posts with no match get an Also read line instead. Then Inbound Done flips to true.

    Webflow CMS item update
  5. 05

    Log every link

    Every link added is appended to a log tab in the keyword sheet: which post links to which.

    Google Sheets

03The keyword register

  • Phrases per postEach post has a few short phrases that can be matched in other posts' text.
  • From Search ConsoleAbout half of the phrases come from the queries the post already ranks for.
  • From ClaudeThe rest are generated from the post body, to cover what the queries miss.
  • The top 100A second tab lists the top 100 posts by traffic, refreshed periodically. Only these can receive links back to a new post.

05Guardrails

  • Done switchesOutbound Done and Inbound Done stop the engines' own edits from setting off runs on other posts.
  • Refreshes are skippedAn older post being edited already has both switches on, so neither engine runs. The content team can edit freely.
  • Webflow 409The post was never published, so it can't be edited through the API yet. Publish it first.
  • Webflow 400An item update is missing its name or slug. The update has to pass both through.
  • A cascade of runsIf executions start piling up, deactivate both engines and check the switches before turning them back on.

06Outcome

2directions linked for every new post, in and out
0editors involved at publish time
5Also read lines at most per post, never repeated

Every new post is linked in both directions within minutes of publishing. Routine refreshes never trigger linking, and the full log means any link can be audited or reversed.

07Operating it

  • Re-link a postTurn its two switches off and republish it. Both engines run again for that post.
  • Remove a linkFind it in the log tab, then edit it out of the post that holds it.
  • Change who can link backRefresh the top 100 tab. Only posts on it receive inbound links.
  • Better matchesAdd or tidy phrases in the register. Short, specific phrases match best.
