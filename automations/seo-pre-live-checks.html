01Problem

Pages went live with SEO mistakes nobody saw until they were indexed.

Missing canonicals, no schema, the wrong robots directive and empty alt text all reached production. The SEO lead usually found them after the pages were already in the index. Checks before launch depended on someone remembering to run them.

Ad landing pages made it worse: they follow the opposite indexing rule from every other page, which made the mistake easy to make in either direction.

02Flow

One n8n workflow, started by a publish to the Webflow staging domain. Each run audits one page.

  1. 01

    Publish event and guard

    A staging publish starts the run. n8n checks whether the page already exists on the production domain. If it does, the run stops, so edits to live pages never send alerts.

    Webflow publish event · HTTP Request
  2. 02

    Fetch and parse

    The staging page is fetched and its HTML is parsed.

    HTTP Request · Code
  3. 03

    Run the eight checks

    Title and description length, OG image, canonical, JSON-LD, BreadcrumbList, image alt text and robots. Blog posts get one more check on their Article schema.

    Code
  4. 04

    Rank the failures

    Each failure is ranked P0, must fix before publishing, or P1, fix before go-live.

    Code
  5. 05

    Report to Slack

    A report goes to the SEO channel: page name, page URL, staging link, overall status, every failure with its reason, the checks that passed, and any manual steps.

    Slack
  6. 06

    Manual actions

    Some fixes need a person, for example confirming the slug with the page owner. The report lists them.

    Slack

06Guardrails

  • Live pages are skippedIf the page already exists on production, the run stops. Edits to live pages never send alerts.
  • Two indexing rulesAd pages under the ads path must be noindex, nofollow. Everything else must be index, follow. The check picks the right rule for each page.
  • Token expiryIf the Webflow API token expires, checks stop firing. Renew it, then republish.
  • Old publishesA staging publish older than 60 minutes doesn't trigger a run. Republish to staging to start a fresh one.

07Outcome

2opposite indexing rules applied automatically

The P0 and P1 ranking tells developers what blocks the launch and what can wait, and the common ad-page mistake can't ship.

08Operating it

  • Run the checks againRepublish the page to staging. A fresh report arrives a few minutes later.
  • Ad pagesKeep ad landing pages under the ads path so the noindex rule applies to them.
  • Blog postsFill in the author and both dates so the Article check passes.
  • Read the reportFix every P0 before publishing. P1s can follow, as long as they're done before go-live.
